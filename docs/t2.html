02

把“打分”变成 0 到 1 之间的数

假设要把彩色豆子分进两个盒子，每颗豆子有两个测量值 x₁、x₂。T1 用直线预测一个数；这次仍然先做加权求和：z = w₁x₁ + w₂x₂ + b。z 可以很大，也可以是负数，还不是概率。

接着把 z 放进一条 S 形曲线 sigmoid。z = 0 时输出 0.5；正得越多越接近 1；负得越多越接近 0。模型给出的 p，是它分配给“类别 1”的概率。这是模型的估计，不是世界保证会兑现的承诺。

最后才轮到阈值。若 p ≥ 0.5 就判为 1，是一种规则；把规则改成 p ≥ 0.8，原来的 p 并不会跟着改变。像提高比赛的及格线，分数本身没动，通过的人却可能少了。

数据走过的三站
  1. 打分z = w₁x₁ + w₂x₂ + b
  2. 压缩p = 1 / (1 + exp(−z))
  3. 决定预测类别 = p ≥ 阈值 ? 1 : 0

固定阈值对应固定 z。在二维平面上，这通常是一条直线。sigmoid 把分数变成概率，却没有让逻辑回归突然能画任意弯曲的边界。

纸上算一颗豆子

取 x = (1, 0)，真实类别 y = 1，起点 w₁ = w₂ = b = 0。于是 z = 0，p = 0.5。二元交叉熵是 −log(0.5) ≈ 0.6931。

dz = p − y = −0.5dw₁ = dz × x₁ = −0.5db = −0.5

步长取 0.1：w₁ 变成 0.05，w₂ 仍是 0，b 变成 0.05。新的 z = 0.1，p ≈ 0.5250，损失降到约 0.6444。注意：这个点的概率更接近 1 了，但若阈值是 0.8，它仍被判为 0。

真实网页每一步会平均 48 个训练点的梯度，不会只照顾一颗豆子。训练目标是降低交叉熵，而不是直接数“有几个猜对”。

03

看懂四个格子，才知道“准”是什么意思

动手 1

只改规则，不改知识

先学习 100 步，再把阈值从 0.50 改为 0.80。盯住同一个测试点：概率和交叉熵不动，决定线与四格统计会动。阈值越高，判为 1 的数量不会增加。

动手 2

重叠的点不能凭空分开

把重叠改成“多”，重新学习。不同标签可能出现在相近位置。增加训练步数也无法保证把它们都分对。这组实验换了数据，不能把单次差异当作普遍结论。

动手 3

0.9 不等于“肯定正确”

查看模型很自信却分错的点。如果真实任务中的数据变了，概率也可能失准。校准、独立测试、误判代价与类群分布，都需要另外检查。

概率回答“模型有多相信”；阈值回答“我们准备采取什么决定”。两者要分开讨论。

为什么只报“准确率”有时会误导？

假设 100 个例子里只有 1 个正类，全部猜 0 就有 99% 准确率，却漏掉了唯一的正类。本网页故意各放 24 个测试点，便于理解四格统计；完整 Python 还比较正类较少的情况。真实任务应一起看漏判、误判、类别比例和决定的代价。

04

这张网页算了什么，Python 又做了什么？

网页是真实运行的 JavaScript 逻辑回归：稳定 sigmoid、二元交叉熵、全批量梯度和参数更新。为让每次打开都可重复，使用固定种子的 Mulberry32 与 Box–Muller 生成两组各 48 点的数据；标签交替且严格平衡。训练种子 42，测试种子 1042。

这不是原 Python 运行结果的镜像。原版使用 NumPy 随机数、160 个训练点、120 个测试点、500 步、学习率 0.15，并比较重叠、类别比例和 0.5 / 0.8 阈值，还做数值梯度检查与参数保存后重载验证。网页的得分只能解释当前网页数据。

实验约定与可检查的限制
  • 所有计算都在浏览器本地进行，不上传输入，无需登录。
  • 修改阈值和查看点不会更新模型；修改重叠会清除旧模型。恢复默认同时恢复阈值、数据与第 0 步。
  • 测试标签只用于评估和绘图，不进入梯度。图中坐标视窗按当前全部训练与测试点自动设置。
  • 初始概率都是 0.5；阈值恰好为 0.5 时，按 p ≥ 阈值 的约定全部判为 1。
  • 网页没有宣称概率经过校准，也没有把合成豆子实验当作医疗、金融等真实决策系统。
