02

把工作状态和存储空间分开

RNN 把过去压进一个隐状态。外部记忆则把存储空间另列成矩阵 M：每一行是一个槽位，每个槽保存一个向量。控制器决定怎样分配读写权重，记忆模块负责执行具体运算。

最直接的是硬寻址：给目标槽权重 1，其他槽权重 0。读取就拿到那一行；写入则只修改它。软寻址给多个槽分配小数权重，因此可以混合读取，也可以同时改动很多槽。

本页和原 Python 的控制器都由人手指定，没有通过数据学到“何时写、写哪里、读什么”。把矩阵放在网络外面，并不会自动产生自主记忆能力。这里要检查的是存储模块的算术与失败方式。

两条真正执行的公式
  1. 读取r = Σᵢ wᵢ Mᵢ
  2. 写入M′ᵢ = Mᵢ ⊙ (1 − wᵢ e) + wᵢ a

e 是各维的擦除比例，取值 [0,1]；a 是添加向量；⊙ 表示逐元素乘法。网页把 e 的三个分量设成同一滑块值，原函数允许各维不同。

03

软读取与擦除写入，都能手算

两个槽的读取

设 M₁=[1,0]、M₂=[0,1]，读取权重是 [0.25,0.75]。那么 r=0.25×[1,0]+0.75×[0,1]=[0.25,0.75]。这不是选中了第二条，而是混合了两条。

硬覆盖与错误覆盖

默认六槽矩阵中，给槽 2 权重 1、擦除 e=[1,1,1]、添加 a=[2,3,0]，原槽 2 会完全变成 [2,3,0]，其余槽逐值不变。点击“正确覆盖槽 2”即可复现原 Python 的这一步。

现在从同一初始矩阵出发，把写权重换成 [0.6,0.4,0,0,0,0]。槽 1 变成 [1,0,0]×0.4 + [2,3,0]×0.6=[1.6,1.8,0]；槽 2 变成 [0,1,0]×0.6 + [2,3,0]×0.4=[0.8,1.8,0]。一次错误寻址同时污染了两个槽。

两个演示按钮都会明确回到初始矩阵后再写，避免把“第二次错误写入”误当成“同一起点的反事实比较”。表格记录刚才的写入权重；右侧条形则会随更新后的矩阵重新计算，是新的读取权重，两者不要混淆。

04

内容寻址：相似，未必相等

如果不知道目标槽号，可以比较一个键 k 与各槽内容的余弦相似度，再计算 w=softmax(β·cosine)。β 越大，在分数不同的情况下权重通常越集中。本页的零向量与任何向量的余弦定义为 0，避免除以零。

默认用 B=[0,1,0] 查初始矩阵，六个相似度是 [0,1,0,0,0,0]。β=8 时，槽 2 权重是 e⁸/(e⁸+5)≈0.998325。它接近 1，但软读取仍含少量其他槽的贡献。

把键换成零向量，或让 β=0，所有分数相同，权重都为 1/6。零键不会神奇地发现正确地址；最高权重并列时，页面会列出所有并列槽，而不假装有唯一命中。

覆盖槽 2 为 [2,3,0] 后，重新用 B 查询，目标槽的方向已经改变，余弦不再是 1。内容寻址把存储内容也当作匹配特征，写入本身会改变未来的检索行为。

四个值得动手的对照

  1. 清空矩阵后，用任意键读取：输出为零，权重均匀
  2. e=1、硬写：用新向量替换整个目标槽
  3. e=0、硬写：保留原值，再把新向量加上去
  4. 保持软写，多次点击：非目标槽也可能持续改变

反复软写不等于一次硬写；变动的权重、部分擦除和累积添加都会影响轨迹。

05

外部记忆解决容量，不自动解决可靠性

寻址风险

读错和写错不是一回事

读错通常让这次输出混杂；写错还会改变存储本身，影响以后每次读取。需要分别检查地址选择、存储变化和输出误差。

训练边界

可微分不代表已经学会

软读写可以成为可微系统的一部分，但这里没有训练控制器。成功复制给定槽位，只说明手写操作按预期执行。

系统边界

矩阵不是完整知识系统

本实验没有文档检索、引用来源、权限、冲突处理或长期更新策略；不能把它当成已实现的 RAG 或长期记忆助手。

原 T9 还将记忆保存为 JSON 再载入，核对往返误差，并比较正确键、错误键和误写地址。网页保留相同读写与内容寻址机制，增加交互操作；页面状态不会持久保存到服务器。

真正困难的不只是“放得下”，还包括“读对地方、写对地方，并知道自己何时读写错了”。
