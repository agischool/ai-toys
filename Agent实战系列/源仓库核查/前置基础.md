## micrograd：把梯度算清，不把标量引擎当训练大模型项目

主要入口：

- [micrograd/engine.py](https://github.com/karpathy/micrograd/blob/7bc720e951fe422b8f8814aa5aa1b64121d26b4c/micrograd/engine.py)：`Value` 保存标量和梯度；加法、乘法、幂和 ReLU 建立运算关系；`backward()` 按拓扑顺序反向调用局部求导逻辑。
- [micrograd/nn.py](https://github.com/karpathy/micrograd/blob/7bc720e951fe422b8f8814aa5aa1b64121d26b4c/micrograd/nn.py)：`Module`、`Neuron`、`Layer`、`MLP` 及 `zero_grad()`、参数集合，连接自动微分与参数更新。
- [test/test_engine.py](https://github.com/karpathy/micrograd/blob/7bc720e951fe422b8f8814aa5aa1b64121d26b4c/test/test_engine.py)：将前向值和梯度与 PyTorch 结果比较。本次只读，没有通过测试的实测结论。
- [demo.ipynb](https://github.com/karpathy/micrograd/blob/7bc720e951fe422b8f8814aa5aa1b64121d26b4c/demo.ipynb)、[trace_graph.ipynb](https://github.com/karpathy/micrograd/blob/7bc720e951fe422b8f8814aa5aa1b64121d26b4c/trace_graph.ipynb)：README 指定的分类训练和计算图入口，本次未逐单元检查或运行这两本 notebook。

代码中梯度使用累加，能解释同一数值沿不同路径影响结果时，为什么各条路径要相加。训练时的清梯度与参数更新也值得单独观察。README 所述约 100 行是引擎、另约 50 行是网络库，不是完整大语言模型约 100 行。

核心 engine/nn 不要求张量框架，但原测试使用 PyTorch；可视化和 notebook 环境又有另外的依赖。正文应区分「阅读标量引擎」「自行做有限差分检查」「跑原测试」「重跑分类演示」，不统一写成零依赖训练教程。

它对 nanochat 的价值是帮助读懂损失、梯度、优化器及参数更新；对 autoresearch 的价值是知道训练实验到底改变了哪些可训练量。没有必要先用标量引擎重写一遍现代训练栈，才允许读者进入主项目。原 README 新链接的 microgpt 是额外材料，本次没有核查其代码、版本或许可，不自动加入必修。

## minbpe：理解文本与 token 的契约

主要入口：

- [minbpe/base.py](https://github.com/karpathy/minbpe/blob/1acefe89412b20245db5a22d2a02001e547dc602/minbpe/base.py)：相邻对计数、合并、词表、保存及加载；基类的 train/encode/decode 是留给子类的接口。
- [minbpe/basic.py](https://github.com/karpathy/minbpe/blob/1acefe89412b20245db5a22d2a02001e547dc602/minbpe/basic.py)：从 UTF-8 字节开始，训练合并规则；编码按已有合并顺序处理，解码先连接字节。没有正则切分或特殊 token 支持。
- [minbpe/regex.py](https://github.com/karpathy/minbpe/blob/1acefe89412b20245db5a22d2a02001e547dc602/minbpe/regex.py)：按类别预切分、独立合并及特殊 token 的显式处理。
- [minbpe/gpt4.py](https://github.com/karpathy/minbpe/blob/1acefe89412b20245db5a22d2a02001e547dc602/minbpe/gpt4.py)：包装 tiktoken 的 `cl100k_base` 合并表和字节映射；它是预训练分词器包装，`train`、`save`、`load` 明确不提供相应实现，不能把所有 tokenizer 子类说成相同功能。
- [exercise.md](https://github.com/karpathy/minbpe/blob/1acefe89412b20245db5a22d2a02001e547dc602/exercise.md)：从 Basic 到 Regex、与特定 tiktoken 编码比较，再到特殊 token 和延伸练习；不是每一步都必须进入主线。

值得制作的新增问题是「训练合并表与使用合并表有何区别」「一个 token 为什么可能只是一段 UTF-8 字节」「编码与模型权重怎样保持约定一致」。不要沿用 README 中「所有现代 LLM 都使用此算法」的泛化说法，也不以旧类名推定今天所有 GPT 产品的 tokenizer。

还有一个容易漏掉的环境边界：[requirements.txt](https://github.com/karpathy/minbpe/blob/1acefe89412b20245db5a22d2a02001e547dc602/requirements.txt) 列出 `regex` 和 `tiktoken`；[包入口](https://github.com/karpathy/minbpe/blob/1acefe89412b20245db5a22d2a02001e547dc602/minbpe/__init__.py) 同时导入 Basic、Regex 与 GPT4 类。因此 Basic 算法主要使用标准库，不等于直接按原包导入就没有第三方依赖。制作时要检查实际安装和导入路径，不能仅根据 basic.py 的几行 import 宣称零依赖。

对 nanochat，重点是理解分词器作为训练与推理契约的角色，具体接口、词表和特殊 token 必须另查目标版本；不能默认用 minbpe 生成的文件就能直接替换其分词器。对 autoresearch，应先查主实验允许改变哪些对象，再决定是否讨论分词器；不能仅凭两个项目都涉及 token，就让读者随意更换评测输入的编码约定。

## 按需选学的工作包与拆并条件

以下名称是工作包标签，不是篇号，也不意味着最终一定各写一篇。每个包先确定新增产物和证据，再决定并入主线一节、成为可选附录，或拆成独立文章。

### 梯度与参数更新

**来源组合：** micrograd engine/nn ＋ Zero to Hero 的同主题讲解。读者若已能解释共享节点梯度累加、清梯度及一步更新，可直接跳过。

**拟产物与验收：** 选择小型标量计算图，手算、自动求导、有限差分对照；另演示未清梯度的结果差异。尚未运行，不填测量值。只做局部导数校验时不需要训练或模型服务；要重跑原测试则另配 PyTorch 环境。

**拆并条件：** 如果主线只需解释 loss/backward/update，把最小图作为训练入口的旁栏；只有需要逐操作实现、共享路径反例与原测试对照时才独立成文。不要把课程 notebook 的同一推导另开一篇。

### 文本、字节、合并表与模型接口

**来源组合：** minbpe Basic/base ＋ 课程 tokenizer 讲解；Regex 与特殊 token 是后续可选扩展。

**拟产物与验收：** 用原创短文本展示合并过程，检查合法输入的 encode/decode 往返及 save/load 前后编码一致性；加入中文、空白、emoji 和未见过组合的对照。解码任意碎片 token 可能遇到不完整 UTF-8，不能把 `errors="replace"` 的显示结果当原文无损复原。短语料没有足够相邻对时，应在制作前设计词表预算及停止处理，避免照抄任意大的 `vocab_size`。

**拆并条件：** 字节与合并规则可合成一个最小实验；只有正则边界或特殊 token 对目标训练/聊天流程有直接影响时，才拆出进一步工作包。与特定 `cl100k_base` 对齐是扩展核查，不是学完分词的通行证，也不是 Agent 安全方案。

### 下一 token 目标、分集与最小生成基线

**来源组合：** Zero to Hero 的 bigram/MLP；nanochat 的实际训练入口由主线另行核查。

**拟产物与验收：** 用小语料构造输入与目标，解释采样和损失，先按完整样本拆训练/开发/测试再构造窗口；区分训练损失、保留集损失及实际生成。重跑训练时固定种子、步数、数据哈希和资源上限，保存失败或没有改善的结果，不只展示顺眼的文本。

**拆并条件：** 已理解输入目标及训练流程的读者可跳过 bigram/MLP 重训，直接从 nanochat 的数据与目标接口进入。若新人看不懂张量形状，单独保留一个基线实验；只有比较不同模型的学习行为才需要拆分 bigram 与 MLP。不要让完整重训所有 makemore notebook 成为继续主线的门槛。

### 张量梯度与训练诊断

**来源组合：** Zero to Hero 的激活、BatchNorm 和手写张量反向传播练习。适用对象是想修改训练代码、需要理解训练异常的开发者。

**拟产物与验收：** 选择目标主项目实际涉及的一段计算，记录形状、前向数值、梯度与数值/框架参考差异；在缩小案例上定位一次实现错误。若原实验涉及特定层与目标项目不同，先说明差异，不能把 BatchNorm 教程直接当作所有现代语言模型的层结构。

**拆并条件：** 未发生相关实现需求时，保留选学链接；需要从头实现高效训练算子时才拆成多次练习。它是训练工程准备，不是自主研究 Agent 已经学会排错的证据。

### 进入 nanochat 与 autoresearch 的阅读门槛

对 nanochat，先确认能把「原文—token—训练目标—损失—更新—评估/推理」对应到实际代码；缺哪一段再回上述工作包。不能因读过 micrograd，就假定已经核查了 nanochat 的分布式、精度、优化器或资源要求。

对 autoresearch，先明确被修改的训练对象、固定的评估规则、实验预算、保留/撤回依据，以及由谁产生代码修改。这些内容应从其实际源仓库确定。读过梯度和分词只是帮助理解实验对象，并不等于实现了自主实验循环。固定规则遍历配置的脚本也不能包装为真实模型 Agent 自主研究。

这两个主项目的最小运行、模型行动或训练证据由对应源核查与制作任务负责；本文件没有验证其环境、成本或性能。是否需要 nanoGPT 或 llm.c 作过渡，也应按目标代码的理解缺口决定，不强加一条七仓库全走完的路线。
